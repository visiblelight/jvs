# Plan 025：ToDo 本机草稿与登录恢复

日期：2026-11-09

状态：实现完成并通过本地验证。用户已授权提交、推送 main 并发布生产，由 Test & Deploy 流程完成持续集成与自动部署；发布结果以该提交对应的 Actions 记录为准。

## 问题和范围

两端收到 401 后立即跳转登录，ToDo 表单仅在组件内存中，导致长文丢失。第一版覆盖管理端和移动端的新建、编辑事项；保留现有登录接口。自动续期、跨设备云草稿及其他业务表单留待后续，不延长令牌有效期来替代草稿保护。

## 实施顺序

1. 增加独立的本机草稿存储：按后端地址、前端应用、账号、草稿 ID 隔离，保存完整表单、事项 ID、原事项版本与保存时间。正文只进入浏览器存储，不放进 URL 或日志；URL 只记录当前草稿 ID。
2. 输入后短暂防抖保存；提交、关闭、路由离开、页面隐藏前同步刷新备份。显示保存状态；存储不可用、空间不足等错误明确提示，提供复制／下载，未备份成功时阻止应用内离开。浏览器强制关闭无法完全保证，beforeunload 只作补充，不能作为唯一保存时机。
3. 页面列出当前账号草稿并支持恢复、明确丢弃。刷新及登录返回后恢复原编辑框，不自动提交。仅服务端明确提交成功或用户确认丢弃后删除草稿；失败、超时和断网均保留。超时提示先核对事项列表再重试，防止用户无意重复创建。
4. 多窗口采用 Web Locks 独占当前草稿；被占用或浏览器不支持锁时另存独立副本，保留原稿。不同草稿独立键值，不使用共享数组覆盖。编辑稿恢复与提交时核对服务器更新时间；已变化或原事项不可访问时保留草稿、提示并允许另存新事项。
5. 统一登录失效处理：先保存编辑器，再清除过期登录状态并跳转；返回路径仅接受站内路径。登录失败不覆盖返回地址，并发或旧令牌的 401 不重复跳转／清除新登录。重新登录刷新应用内存，避免旧账号业务状态残留；恢复稿只读取登录账号对应命名空间。草稿提交额外核对账号，避免另一个窗口切换账号后提交给错误账号。
6. 完成两端自动测试、生产构建及隔离环境浏览器验收，补充开发说明。

## 验收

- 长文、Markdown 图片链接、分类／标签／时间／开关／状态完整往返。
- 登录过期 → 发布失败 → 重新登录 → 原草稿恢复，用户手动提交一次。
- 刷新、关闭编辑框后重新打开、路由跳转、断网与 5xx 均保留。
- 成功提交清理当前稿；丢弃需明确确认；多窗口互不覆盖。
- 不同账号、不同后端、不同应用不串稿；旧 401 不使新登录失效；返回地址不能跳到外站。
- 存储失败不会虚报成功；仍可复制或下载；应用内跳转受保护。
- 编辑目标已更新或删除时不直接覆盖，保留文本并可另存新事项。

本机草稿不会跨设备同步，清除站点数据或隐私模式结束可能移除草稿，界面明确说明。实现依据：[localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage)、[Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)、[beforeunload 限制](https://developer.mozilla.org/en-US/docs/Web/API/Window/beforeunload_event)。

- 编辑目标在测试库更新后，旧草稿保存被阻止并显示冲突；另存新事项后刷新仍按新建恢复，可成功提交，原事项内容保留。
- 通过仅存在于本机测试构建的故障注入模拟存储配额错误：显示失败、阻止关闭，全文可复制；解除故障并重试后可关闭，再从草稿列表恢复。测试注入已移除。
- 更新 ToDo 功能、认证客户端行为、浏览器草稿结构及开发验证说明；API 和数据库结构无变更，无迁移。

边界：客户端版本检查不等同于服务端原子条件更新；超时结果不自动重试，尚无幂等创建协议。强制结束浏览器或清除站点数据不可保证恢复，图片上传中的二进制不纳入本机草稿。
