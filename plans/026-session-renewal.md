# Plan 026：自动续期与可撤销登录会话

日期：2026-11-18

状态：实现与本地验收完成。用户已授权编码、测试、提交并发布生产，无需再次等待确认；生产发布由 main 自动流水线执行。

## 目标与规则

管理端和移动端正常使用时自动保持登录，不再因访问令牌的 24 小时有效期每天重新输入密码。采用服务端会话与 HttpOnly 续期 Cookie；访问令牌继续由 `ACCESS_TOKEN_EXPIRE_MINUTES` 控制（现网 1440 分钟），不靠无限延长访问令牌解决问题。

- 续期会话在连续 30 天未成功续期后失效；从首次登录起最多保持 90 天，之后重新认证。
- 发起业务请求／重新打开页面时检查是否即将到期；必要时先续期。业务请求收到认证 401 时续期并最多重试一次。后台空置不定时保活。
- 主动退出撤销当前会话；修改密码、管理员重置密码或停用账号撤销该账号的全部会话。
- 网络中断、超时、5xx 不视为退出登录，不清除登录凭据和草稿。
- 旧版 JWT 可使用至原到期时间；升级后需重新登录一次建立续期会话，已到期旧令牌不作为长期会话凭证。

## 实施顺序

### 1. 服务端会话与迁移

新增 `auth_sessions` 表，保存随机会话 ID、用户 ID、当前与上一代续期凭证哈希、并发宽限截止时间、创建／最近续期时间、空闲／绝对到期时间、撤销时间。原始续期凭证不落库、不进入日志或 localStorage。用户表新增 `token_version`，默认 0，兼容已有用户和旧 JWT。

登录生成持久 HttpOnly Cookie，默认 Secure、SameSite=Lax、仅 `/api/admin/auth` 路径、无 Domain。生产使用 HTTPS；本地 HTTP 测试显式关闭 Secure。分离部署须配置精确可信 Origin、带 credentials 请求；真正跨站部署可显式配置 SameSite=None + Secure，但仍受浏览器第三方 Cookie 限制。

刷新时轮换凭证并延长空闲有效期，不能越过绝对期限。数据库按用户、会话的固定顺序加锁；上一代凭证提供 30 秒并发宽限，同一宽限窗口返回同一新凭证，避免多个窗口竞争导致误退出。后继凭证通过服务端 HMAC 确定性生成，数据库仅保留哈希；宽限外重放已知上一代凭证则撤销会话。随机错误凭证不允许仅凭会话 ID 撤销别人的会话。

访问 JWT 带会话 ID、用户认证版本和签发时间；每次鉴权检查会话未撤销、未到期和账号版本。旧 JWT 仅在用户版本仍为 0 时兼容。改密／停用更新认证版本并撤销会话，防止重新启用后旧凭据复活。

### 2. 认证接口与浏览器边界

- `POST /login`：保持原响应兼容，建立会话并设置续期 Cookie；同浏览器切换账号撤销已验证的原 Cookie 会话。
- `POST /refresh`：只使用续期 Cookie，返回新访问令牌；核对客户端预期会话／账号，防止其他窗口切换账号后续期到错误账号。
- `POST /logout`：撤销当前 Cookie 会话并清除 Cookie；幂等，退出失败须明确告知用户。
- 续期、退出要求专用请求头，浏览器 Origin 必须匹配配置的可信前端；拒绝普通跨站表单。认证响应使用 no-store。
- 刷新失败不盲目清 Cookie，避免旧请求的响应覆盖另一窗口的新登录。

### 3. 两端自动续期协调

增加独立会话客户端与纯逻辑测试入口。续期使用不带业务响应拦截器的请求，防止循环；同页面并发请求共享一次续期，支持 Web Locks 的同源多窗口串行处理登录／续期／退出，后端宽限处理不支持锁及不同前端 Origin 的竞争。

保存登录状态代次并核对会话身份，过时响应不得恢复已经退出的登录或覆盖另一账号。显式退出／明确认证失效后记录本机退出状态，不因再次刷新页面悄悄恢复 Cookie 登录。业务请求在续期前后均核对草稿所属账号；仅对明确认证 401 重试，网络未知结果不重放写请求。

页面路由允许刷新恢复会话；已加载账号时，临时续期故障保留当前页面和账号，业务 API 仍须续期成功才发送请求。首次加载尚无用户资料时，`/me` 网络失败展示可重试登录页面并保留本机凭据。自动续期失败且明确需要重新认证时，继续沿用 Plan 025：先备份草稿、保留返回位置，再跳转登录。

### 4. 验证、文档与发布

- 后端：登录 Cookie 属性、正常／过期访问令牌续期、轮换与重放、并发刷新、空闲及绝对期限、退出、改密／禁用撤销、旧 JWT、Origin／请求头、账号切换及无缓存响应。
- 数据迁移：SQLite 与 PostgreSQL 空库、已有数据升级和模型一致性；不清理生产业务数据。
- 前端：请求前续期、并发合并、401 单次重试、临时网络失败保留登录、跨账号与退出竞争、草稿保护回归、两端同源／分离构建。
- 隔离浏览器验收：两端模拟访问令牌到期后继续读写且保持编辑内容，退出后不会自动恢复；测试不写生产事项。

- 回退可切回上一应用提交，保留新增表／列，不执行破坏性降级；新版创建的访问令牌仍有原到期时间，旧应用不提供自动续期。

依据：[OWASP 会话管理](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)、[RFC 9700 刷新令牌保护](https://www.rfc-editor.org/rfc/rfc9700.html#section-4.14)、[Cookie 属性](https://developer.mozilla.org/en-US/docs/Web/HTTP/Reference/Headers/Set-Cookie)。30／90 天是本项目选定的产品策略，不是上述资料规定的统一期限。
