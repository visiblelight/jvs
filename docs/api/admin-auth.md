# 管理后台 — 认证接口

Base Path: `/api/admin/auth`

---

## POST /login

登录并获取 JWT 访问令牌，同时建立可续期会话。浏览器请求需要携带 credentials；若携带 Origin，必须精确匹配后端 CORS_ORIGINS。

**请求体** (JSON):

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| username | string | 是 | 登录账号 |
| password | string | 是 | 登录密码 |

**成功响应** (200):

```json
{
  "access_token": "eyJhbGciOiJIUzI1NiIs...",
  "token_type": "bearer"
}
```

**失败响应**:

| 状态码 | detail | 说明 |
|--------|--------|------|
| 401 | 用户名或密码错误 | 账号不存在或密码不匹配 |
| 403 | 用户已被禁用 | 账号已被停用 |

成功响应设置 `jvs_refresh` Cookie：HttpOnly、默认 Secure、SameSite=Lax、Path=/api/admin/auth，不设置 Domain。续期凭证不出现在 JSON 中。访问令牌有效期继续由 `ACCESS_TOKEN_EXPIRE_MINUTES` 控制（生产 1440 分钟）；会话默认连续 30 天未成功续期失效，首次登录 90 天后绝对失效。同浏览器再次登录会撤销已验证的原 Cookie 会话。

所有 `/api/admin/auth/` 响应（包括错误）带 `Cache-Control: no-store`。

## POST /refresh

通过 HttpOnly Cookie 自动续期，不需要 Authorization。必须发送 `X-JVS-Session: 1` 和 JSON 请求体；浏览器若携带 Origin，必须精确匹配可信前端。

```json
{"session_id": "JWT 中的 sid（可选）", "user_id": 1}
```

两个字段均可省略或为 null；首次从 Cookie 恢复时发送 `{}`。已持有访问令牌时应发送其 sid 和用户 ID，防止其他窗口切换账号后恢复到错误账号。

成功返回与登录相同的 JSON，并更新 Cookie。凭证轮换使用 30 秒并发宽限；窗口内旧凭证返回相同后继凭证，宽限后重放上一代凭证会撤销会话。刷新失败不清 Cookie，以免过时响应覆盖另一窗口的新登录。

| 状态码 | 说明 |
| --- | --- |
| 401 | Cookie 缺失、无效、会话过期／撤销或账号已停用 |
| 403 | 缺少专用请求头或 Origin 不受信任 |
| 409 | Cookie 会话与客户端预期账号／会话不符 |

## POST /logout

携带 Cookie、`X-JVS-Session: 1` 和 JSON `{"session_id": "当前 JWT 的 sid"}`；旧版无 sid 时发送 `{}`。Origin 规则同续期。

成功返回 `204 No Content`，撤销当前 Cookie 会话并清除 Cookie；重复退出或 Cookie 缺失仍返回 204。预期会话不匹配返回 409，且不撤销／清除其他窗口的新会话。退出后的新令牌立即失效；旧版无会话 JWT 只能清除本机副本，仍受原到期时间和账号版本约束。

## GET /me

获取当前登录用户信息。需在请求头中携带 Token。

**请求头**:

```
Authorization: Bearer <access_token>
```

**成功响应** (200):

```json
{
  "id": 1,
  "username": "admin",
  "is_active": true,
  "is_superuser": true,
  "avatar": null,
  "created_at": "2026-01-01T00:00:00Z",
  "modules": ["todo", "news", "access_key"]
}
```

> 超级管理员的 `modules` 始终为空数组（隐式拥有全部板块权限）；普通用户则按授权列出。

**失败响应**:

| 状态码 | detail | 说明 |
|--------|--------|------|
| 401 | 无效的认证凭据 | Token 缺失、过期或无效 |
| 403 | 用户已被禁用 | 用户账号已停用 |

## PUT /password

修改当前用户密码。

**请求头**: `Authorization: Bearer <access_token>`

**请求体** (JSON):

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| old_password | string | 是 | 当前密码 |
| new_password | string | 是 | 新密码（最少 6 位） |

**成功响应**: `204 No Content`。同时清除续期 Cookie、撤销该账号所有会话并递增认证版本；全部设备及旧版 JWT 均需重新登录。管理员重置密码或停用账号也会撤销全部会话，重新启用不会恢复旧凭据。

**失败响应**:

| 状态码 | detail | 说明 |
|--------|--------|------|
| 400 | 旧密码不正确 | 当前密码验证失败 |
| 422 | 验证错误 | 新密码不满足长度要求 |

## 图片上传约束（Plan 024）

头像最大 2 MB，通用图片最大 5 MB。服务端解码并验证 JPEG、PNG、GIF、WebP，声明 MIME 必须与真实内容一致；扩展名由服务端确定。单帧最多 2000 万像素，所有帧合计最多 4000 万像素、最多 200 帧，超限或损坏返回 400。头像替换失败保留旧文件。上传目录仅提供有效图片，历史 HTML 或伪装图片 URL 返回 404，并设置 `nosniff`。

## 时间格式（Plan 024）

所有时间点返回带 `Z`（UTC）的 ISO 8601，例如 `2026-11-03T05:00:00Z`，上海客户端显示 13:00。写入截止时间、执行时间、新闻发布时间或提交日历查询边界时必须带 `Z` 或 `+08:00` 等偏移量；无时区时间点返回 422。纯日期 `YYYY-MM-DD` 不做时间点转换。未传字段保持不变，可选字段传 null 可清空。

## 前端登录恢复（Plan 025 / 026）

两端请求前检查访问令牌，到期前最多提前 5 分钟续期；业务 401 先续期并最多重试一次。仅在明确认证失效时，先同步备份打开的 ToDo 草稿，再清除登录状态并转到 `/login?redirect=...&expired=1`；移动端 URL 位于 `/mobile/` 下。网络中断、超时、5xx 保留登录状态和草稿，不自动重放结果未知的写请求。返回地址只接受站内路径，正文不进入 URL。

同页面并发请求共享续期，同源窗口通过 Web Locks 协调。续期响应核对登录代次和账号，不能恢复已退出的会话或覆盖另一账号。主动退出后刷新页面不会自动从 Cookie 登录。旧版 JWT 在原有效期内继续可用，升级后需要重新登录一次建立续期会话。

登录接口本身的 401 仅展示账号或密码错误，不覆盖返回地址。旧令牌请求延迟返回的 401 不清除新的登录。首次进入页面的 `/me` 检查失败时保留目标路由，而不是用尚未进入的当前路由覆盖返回地址。登录成功后整页恢复应用，避免上一账号的内存状态残留。

草稿写入前的客户端账号核对只防止跨窗口误提交，不代替服务端鉴权。草稿无法备份时不会自动离开编辑器，应先复制／下载并重试保存。
